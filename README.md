# 猫传染性腹膜炎（FIP）知识推理演示

> 一个面向猫主人的 FIP（猫传腹）科普问答自演示产品：基于知识图谱的**确定性、可解释**因果推理，全程不依赖大语言模型。

## 这是什么

猫传染性腹膜炎（FIP）是猫科动物中常见且致死率高的疾病，相关科普信息分散、质量参差。本项目尝试用一种**不同于对话机器人**的方式，回答养猫人最关心的问题：

- 不是让大模型"生成"一个看起来合理的答案，而是把知识组织成**因果图谱**，让每一次回答都能**追溯依据**；
- 用户提出的每一个问题，系统都会给出**推理链**——从识别到的实体、意图，到命中的图谱路径与证据，再到最终结论；
- 对明显超出范围或需要紧急就医的情况，系统会主动**提示边界**，而不是强行作答。

它更像一份"会推理的科普资料"，定位为**学习与原型演示**，而非诊疗工具。

## 核心能力

- **自然语言问答**：直接用中文提问（如"传腹的症状有哪些""GS-441524 是什么"），系统解析实体与意图后给出结构化回答。
- **可解释推理链**：每一步推理（实体 → 意图 → 图谱查询 → 证据/风险 → 回答）都在界面上可视化呈现。
- **意图与场景识别**：支持多类细分意图，并区分 `meta`（元问题）与 `emergency`（紧急就医）等特殊场景。
- **边界兜底**：识别到非猫科主体、或属于紧急就医情形时，不强行推理，而是给出明确提示。
- **双知识图谱后端**：图谱数据可在**本地 NetworkX 内存图**与**云端 Neo4j（Aura）**之间切换。

## 设计理念

**为什么不用大模型？**

用非大模型环境可以更好的体现本体+知识图谱在医疗领域的回答能力，以及答案无法溯源。本项目刻意采用**确定性多 Agent 流水线 + 知识图谱**的路线：

- **确定性**：同样的问题得到稳定、可复现的回答，不随时间或随机性漂移；
- **可审计**：每一条结论都能回溯到图谱中的具体节点与路径，方便核查；
- **零幻觉风险**：答案受图谱内容约束，不会凭空编造。

**为什么是知识图谱？**

FIP 相关的概念（病原 FECV/FIPV、诊断、GS-441524 治疗、预后等）之间存在大量**因果与关联关系**。图谱天然适合表达这种结构，也让"为什么这么答"变得可读。

**边界优先**

推理之前先做主体与场景判断：非猫科动物主体直接拦截；紧急情形优先提示就医。安全边界是设计的一等公民，而非事后补丁。

## 系统架构

```
                 ┌──────────────────────────────┐
                 │     Gradio 前端 (app.py)      │
                 │  三栏界面 · 注入 JS 动效交互   │
                 └──────────────┬───────────────┘
                                │ 用户输入
                                ▼
                 ┌──────────────────────────────┐
                 │   Orchestrator 编排层         │
                 │      (core/pipeline.py)       │
                 └───┬────────┬────────┬─────────┘
                     │        │        │
                     ▼        ▼        ▼
               ┌────────┐ ┌────────┐ ┌────────┐
               │ Entity │ │ Intent │ │GraphQry│   ┌──────────┐
               │ 实体解析│ │ 意图识别│ │ 图查询 │   │ Evidence │
               └────────┘ └────────┘ └───┬────┘   │ / Risk   │
                                         │       └────┬─────┘
                                         ▼            │
                                  ┌──────────────────▼──┐
                                  │  Response 生成 + Trace │
                                  └────────────┬─────────┘
                                               │
                                  ┌────────────▼──────────┐
                                  │  GraphProvider 抽象层   │
                                  │  (按 GRAPH_BACKEND 切换)│
                                  ├────────────┬───────────┤
                                  │  Local     │  Neo4j    │
                                  │ NetworkX   │  Aura 云  │
                                  └────────────┴───────────┘

   Boundary Agent：非猫主体 / 紧急就医 场景短路兜底
```

前端（单文件 `app.py`，通过注入 JS 实现动效与交互）接收输入后，交给 `core/` 中的确定性推理包；编排层依次调用实体、意图、图查询、证据/风险等 Agent，最终由 Response Agent 汇总并产出带推理链的答案。图谱访问统一走 `GraphProvider` 抽象，由环境变量在本地与云端后端间切换。

## 界面与交互

项目采用**暖杏奶油系**视觉语言（方案 B / V2），强调低饱和、克制用色、温暖可信：

- **三栏布局**：左侧功能导航、中间对话区、右侧可展开的推理技术面板；
- **Trace 推理面板**：将实体匹配、意图判定、图谱路径、证据与风险逐层展开；
- **动效**：关键面板采用入场/出场过渡、侧边栏滑出等轻量交互；
- 完整设计系统与配色 token 见 `pet-medical-ui`（独立设计目录）。

## 技术要点

- **前端**：Gradio 6.x（单文件 `app.py`，以注入 JS 实现前端行为与交互）
- **语言**：Python
- **推理内核**：`core/` 确定性多 Agent 流水线（无 LLM）
- **图谱后端**：Neo4j（Aura 云实例）与 NetworkX（本地内存图），通过 `GRAPH_BACKEND` 切换
- **承载平台**：ModelScope
